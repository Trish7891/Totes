01
The problem

An agent that executes is a product —
and a liability.

  • ▸A model with a shell can read ~/.ssh, charge a card, or delete a table.
  • ▸Installed "skills" run with full agent permissions — one agent scanned 286 community skills and found a credential stealer in a weather skill.
  • ▸Most products answer this with "trust us." None of them ship proof.

Containment-first is the product, not a feature bolted on afterwards.

02
What it does

Task → cell → verified answer

01

Plan

A model turns the task into a small Python program. It never runs code itself.

02

Dispatch

The program runs in a fresh cell: own namespaces, no network, no host filesystem, capped cpu/memory/disk.

03

Verify

Real stdout returns, scrubbed of credentials, and the run ends with a hash-chained receipt you can re-verify.

Every action goes through one executor. There is no trusted bypass and no "unsafe mode".

Architecture

Control layer, planner, cell, verifier

browser ──▶ FastAPI control layer (Vultr VM) · run store · SSE event stream · hash-chained receipt per run │ plan(task) → code ▼ Planner (model) ──▶ OpenAI-compatible endpoint (swappable; scripted fallback built in) │ code (never executed in-process) ▼ CELL bubblewrap, per run, disposable ├─ new PID / IPC / UTS / net namespaces ├─ no network · host paths absent ├─ /usr /etc read-only · tmpfs /work └─ rlimits: cpu, mem, fsize, nproc, nofile │ stdout/stderr (redacted, capped) ▼ Verifier → receipt {chain_head, policy, manifest}
04
Containment model

Every claim has a test

  • ✓No host filesystem — /home, /root, /mnt never bound, so they do not exist
  • ✓No egress, no DNS — unshare-net, verified by a failing socket and a failing resolver
  • ✓Host secrets never cross in; key-shaped output is redacted on the way out
  • ✓CPU, wall clock, memory, file size, process count all capped; workspace destroyed per call
  • ✕Not claimed: kernel isolation. Namespaces share the kernel — a microVM backend is the upgrade path, and the UI says so.

Declared, not implied

Permission manifest + receipt

  • ▸Each run declares what it may touch, what it may not, and what this layer does not stop.
  • ▸The manifest is generated from the same policy the sandbox enforces — declare and enforce cannot drift.
  • ▸Its sha256 rides inside the receipt; every event hashes the previous one.

08
Honest limits & next

What this is not

  • ▸Shared kernel. A kernel bug escapes the cell; the executor interface was built so a microVM backend drops in without touching orchestration.
  • ▸Single-node run store. Restarting the service drops history — receipts should be persisted first.
  • ▸Planner quality is the model's, not the sandbox's; the sandbox only guarantees that what it does stays inside.

Containment you can check beats containment you're asked to trust.
